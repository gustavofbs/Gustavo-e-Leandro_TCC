\section{Contexto}\label{contextualizacao}

Garantir a qualidade de software é um desafio que se estende desde o início do desenvolvimento de sistemas. Dessa forma, os processos de Verificação e Validação tornam-se fundamentais para incorporar qualidade ao sistema ao longo do ciclo de vida, pois ``determinam se os produtos de desenvolvimento de uma determinada atividade estão em conformidade com os requisitos dessa atividade e se o produto atende ao seu uso pretendido e às necessidades do usuário''  \cite[p.~10, tradução nossa]{IEEE1012-2016}.

Neste trabalho, a ISO/IEC 25010 \cite{ISO25010} foi utilizada como base conceitual, pois ela define modelos que são utilizados como referência para avaliar se um produto de software atende às necessidades das partes interessadas. Ela define dois modelos: Qualidade do Produto e Qualidade em Uso, e eles permitem fazer uma especificação, medição e avaliação da qualidade de software, auxiliando na especificação de requisitos e na identificação de aspectos que impactam a experiência do usuário e o uso do sistema em diferentes contextos.

Os sistemas web modernos muitas vezes utilizam interfaces complexas e dinâmicas que interagem com o usuário em tempo real, o que dificulta a avaliação da qualidade de software. Apesar de a ISO/IEC 25010 \cite{ISO25010} fornecer uma base para especificar e avaliar a qualidade de software, essa avaliação depende principalmente da realização de testes. Nesse sentido, \citeonline{Mughal2025} afirma que:

\begin{citacao}
as aplicações web modernas caracterizam-se por suas estruturas de navegação dinâmicas e complexas, nas quais cada página e interação do usuário compõem uma rede intrincada. As metodologias de teste tradicionais, muitas vezes, não conseguem explorar plenamente esses caminhos complexos, especialmente quando as ações dos usuários são interdependentes e sensíveis ao contexto \cite[p.~1, tradução nossa]{Mughal2025}.
\end{citacao}

Por isso, o foco desta pesquisa é a geração de testes automatizados para Cypress a partir de especificações de Desenvolvimento Orientado ao Comportamento (BDD), utilizando Inteligência Artificial (IA), direcionada para a subcaracterística Testabilidade, que pertence à característica de Manutenibilidade da ISO/IEC 25010 \cite{ISO25010}, pois busca tornar mais eficiente a transformação dos cenários BDD em testes executáveis.

A Inteligência Artificial Generativa, devido aos avanços recentes, permite a geração de código e criação de agentes personalizados, o que pode ser uma alternativa para o desenvolvimento de ferramentas automatizadas que visem aumentar a qualidade de software \cite{Chemnitz2023, Pysmennyi2025}. Um dos problemas que a IA pode ajudar a enfrentar é a fragilidade dos seletores identificadores usados para localizar elementos de interface web, como ids ou seletores CSS. Como consequência disso, os testes automatizados podem quebrar facilmente após mudanças visuais ou estruturais na aplicação. Frameworks modernos de front-end de página única geram estruturas Modelo de Objeto de Documento (DOM) dinâmicas e isso torna os seletores instáveis, fazendo com que alterações na interface exijam retrabalho para reescrever o código dos testes de ponta a ponta \cite{Pysmennyi2025}.

Os cenários em BDD escritos em Gherkin seguem a regra Dado-Quando-Então. Porém, eles são muito abstratos e não possuem detalhes suficientes para identificar elementos de interface com exatidão, o que dificulta a geração de testes automatizados. Segundo \citeonline{Alinezhadtilaki2025}, se os cenários forem mal construídos, podem gerar mal-entendidos, resultando em testes pouco confiáveis e em ineficiências no processo de desenvolvimento.

Dessa forma, a qualidade dos cenários BDD escritos em Gherkin, em termos de clareza, completude e testabilidade, é importante para o sucesso de abordagens automatizadas \cite{Alinezhadtilaki2025, Ferreira2025}, pois cenários sem contexto claro dificultam que as ferramentas consigam compreender a funcionalidade a ser testada.

Ferramentas baseadas em IA dependem de descrições claras e de artefatos textuais explícitos para interpretar corretamente passos e elementos das interfaces \cite{Ferreira2025}, enquanto métodos tradicionais, como Desenvolvimento Orientado a Testes (TDD) e BDD, possuem limitações para lidar com agentes baseados em LLM, pois assumem especificações estáveis e comportamentos determinísticos, o que contrasta com a natureza não determinística e adaptativa desses agentes \cite{Xia2025}.

De acordo com \citeonline{Ferreira2025}, apesar de existirem pesquisas relacionadas à transformação de linguagem natural em testes, são poucos os estudos focados especificamente em gerar testes automatizados a partir de cenários BDD com Modelos de Linguagem de Grande Escala (LLM). Além disso, os poucos trabalhos que geraram testes executáveis a partir de cenários escritos em Gherkin concentram-se em produzir testes para código, como classes Java ou funções Python, e não em testes sobre interfaces gráficas, os quais exigem a identificação de elementos da interface de usuário (UI) \cite{Ferreira2025}.
